PROJECT DOCUMENTATION

A small parser, with explicit behavior.

What it does

The first record is treated as headers. The strict parser handles quoted commas, escaped quotes, multiline cells, CRLF record endings, and a UTF-8 byte-order mark. It reports malformed quoting, repeated or empty headers, uneven record widths, and formula-like cells.

What it preserves

Each field remains a string, including leading zeros and quoted line endings. JSON uses separate header and row arrays so repeated headings cannot overwrite values. Inspection does not invent repairs, infer data types, or validate what the records mean.

How to use it locally

Load the included synthetic example, paste text, or choose a local UTF-8 CSV up to 2 MB. Run the inspection and review the notices. Downloading JSON is an explicit action. You can also open the files in the repository’s docs directory directly in a modern browser.

Command-line checks

The repository also includes CSV catalog preflight and JSON syntax/duplicate-key checks. Their documentation gives commands, examples, and explicit limits. These checks support review; they do not infer missing data or certify every meaning of a record.
